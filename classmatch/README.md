# クラスマッチ ドッチボール 結果入力サイト

| ページ | ファイル | 使う人 |
|---|---|---|
| トップ | index.html | 入口 |
| 審判用 | referee.html | 試合ごとにスコアと内野の残り人数を入力 |
| 本部用 | hq.html | リーグ表・得失点差・決勝トーナメント・全結果（10秒ごとに自動更新） |
| サッカー（本部用のみ） | soccer.html | 結果の入力・リーグ表・得失点差・決勝／3位決定戦 |
| バレーボール（本部用のみ） | volleyball.html | 同上 |

順位は 勝点（勝3・負0）→ 得失点差 の順で決まります。**勝点も得失点差も同じクラスがあるときは、順位決定サドンデス**を行い、本部ページでその結果（勝った順）を入力して確定します（確定するまで準決勝の組み合わせは「暫定」表示）。得点・直接対決を先に使いたい場合は `config.js` の `dodgeball` の `tiebreak` を true にしてください。
各リーグ上位2クラスが準決勝へ（1リーグ1位×2リーグ2位 ／ 2リーグ1位×1リーグ2位）。準決勝の敗者が3位決定戦です。

## 1試合の判定ルール（ゲーム制・引き分けなし）
- 審判は、ゲームが終わるたびに「各クラスの内野の残り人数」を入力します（人数の多い方がそのゲームの勝ち、差が内野差）。
- 最初は2ゲーム分の欄が出ます。勝ちゲーム数が並ぶと3ゲーム目の欄が自動で出ます（2連勝なら出ません）。
- 試合の勝者の決め方は次の順です。
  1. 勝ちゲーム数
  2. 並んだら、勝ったゲームの内野差の合計（多い方の勝ち）
  3. それも同じなら **サドンデス**（審判画面に「サドンデス」の入力欄が出るので、普通のゲームと同じく終了時の内野の残り人数を入力する。勝った方の勝ちゲームに数え、内野差も得失点に加わる）
- 得失点は、試合に勝った側が勝ったゲームの内野差の合計だけです。負けた側が勝ったゲームの内野差は数えません。
  - 例）1組が勝ち(差2)・2組が勝ち(差3)・1組が勝ち(差3) → 1組の勝ち、得失点差 1組 +5（2組の3は数えない）
  - 内野差の合計で決まった試合も、サドンデスで決まった試合も、得失点は勝った側が勝ったゲームの内野差の合計です（サドンデスの内野差を含む）。
- 決勝トーナメントも同じ決め方です（引き分けなし）。
- 設定は `config.js` の `dodgeball` の `games`（最低ゲーム数・最大ゲーム数）で変えられます。

## サッカー・バレーボール（本部用ページだけ）
- 審判ページはありません。**本部ページの「結果の入力」で、試合ごとにスコアを入れて「保存」**します（直したいときは「修正を保存」、消すときは「取消」）。
- リーグの形・対戦の組み合わせはドッチボールと同じ（1リーグ＝五角形、2リーグ＝四角形）。リーグ戦9試合＋決勝＋3位決定戦＝全11試合です。
- **決勝は各リーグ1位どうし、3位決定戦は各リーグ2位どうし**で、リーグ戦が全部終わると対戦カードが自動で決まります。
- 順位は **勝率 → 得失点差**（各試合のスコアの差の合計）の順です。勝率＝（勝ち＋引き分け×0.5）÷試合数。勝率も得失点差も同じなら、抽選やPK戦などで決めた順を本部ページで確定します。
- 引き分け：サッカーのリーグ戦は引き分けOK。決勝・3位決定戦で同点のときは、PK戦（延長）の勝者を選んで保存します。バレーボールは引き分けを入力できません。
- リーグの組み分け・対戦の組み合わせ・進行順は、`config.js` の `soccer`／`volleyball` の `leagues`・`schedule` で競技ごとに変えられます（初期設定はドッチボールと同じ形）。
- 結果は競技ごとに別のシート（`results_soccer`、`results_volleyball` など）に自動で作られて保存されます。**Code.gs は新しい版に差し替えて、再デプロイしてください。**
- 通信がないときの動き（未送信の自動送信・ファイルの書き出し／取り込み）はドッチボールと同じです。

## 設定ファイル（config.js）の見方
- 一番上の `EVENT`（大会名）・`API_URL`（スプレッドシートのURL）・`REFRESH_SEC` は全競技共通です。
- `SPORTS` の中に、`dodgeball`／`soccer`／`volleyball` のブロックが別々にあり、競技ごとに次を設定できます。
  - `leagues` … リーグの組み分け。`classes` は図の時計回りの並びで、隣どうしが対戦します（五角形・四角形など、クラス数に合わせて自動で図になります）。
  - `schedule` … 試合の進行順。
  - `rank`／`points`／`tiebreak`／`advance` … 順位の決め方、勝点、同率のときに使う条件、各リーグから進出するクラス数。
  - ドッチボールだけ `games`（ゲーム数）、サッカー・バレーボールだけ `draw`（引き分けを認めるか）。
- 注意：決勝までの組み合わせは「リーグが2つ」を前提にしています。

## 通信がないグラウンドで使うとき
- **事前準備（重要）**：大会前に、使うChromebook全部で `index.html`・審判ページ・本部ページを、通信できる場所（学校のWi-Fiなど）で一度ずつ開いておく。以後は通信がなくてもページが開く。
- **通信がなくても入力できる**：保存した結果はその端末に残り、画面に「未送信の結果が○件あります」と出る。通信が戻れば自動でスプレッドシートに送られる（ページを開いたままにしておく）。
- **確実な方法はスマホのテザリング**：先生のスマホなどのテザリングにChromebookをつなげば、審判と本部はいつも通りリアルタイムで共有できる。
- **通信が全くないとき**：審判のChromebookで、審判ページ下の「この端末の結果を書き出す」を押してファイルを保存し、USBメモリやニアバイシェアなどで本部の端末に移す。本部ページ下の「結果ファイルを取り込む」で読み込むと、順位表に反映される（同じ試合は上書き）。
- 本部の1台だけで運用する手もある：審判は紙に書き、本部の1台に入力する（API_URL を空にしたテストモードのまま、端末内だけで完結）。
- **サイトを更新（GitHubに再アップロード）したあと**は、各Chromebookで一度だけ、通信できる状態で各ページを開き、Ctrl＋Shift＋R で読み込み直してください。以後は自動で最新になります（設定ファイル config.js は毎回新しく取得するので、API_URL の変更が古いまま残ることはありません）。
- 本番のはずなのに「テストモードです」と出たときも、Ctrl＋Shift＋R を押してください。この端末に本番の記録が残っている場合は、自動で古い控えを消して1回だけ読み込み直します。

## 公開までの手順（約15分）

### A. Googleスプレッドシートに結果を保存する準備（審判と本部でデータを共有するために必須）
1. Googleスプレッドシートを新規作成する（名前は何でもOK）。
2. メニュー「拡張機能」→「Apps Script」を開く。
3. 最初から入っているコードを全部消し、`apps-script/Code.gs` の中身を貼り付けて保存。
4. 右上「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」。
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**全員**
5. 「デプロイ」を押し、権限の承認をして、表示される **ウェブアプリのURL**（`https://script.google.com/macros/s/…/exec`）をコピー。
6. `config.js` の `API_URL: ""` の中にそのURLを貼る。

※ 以前の版の Code.gs をすでにデプロイしている場合は、`results` シートを削除してから、新しい Code.gs で再デプロイしてください（ゲームごとの記録用の列が増えています）。
※ Code.gs を後から直した場合は「デプロイを管理」→ 編集 →「新バージョン」で再デプロイが必要です。

### B. GitHub Pagesで公開する
1. GitHubで新しいリポジトリ（Public）を作る。
2. このフォルダの中身（index.html, referee.html, hq.html, *.js, style.css, apps-script/）をアップロード。
3. リポジトリの Settings → Pages → Branch を `main` / `(root)` にして Save。
4. 数分後に出る `https://ユーザー名.github.io/リポジトリ名/` が入口です。
   - 審判の端末には `…/referee.html`、本部には `…/hq.html` のURLを共有（QRコード化するとCanvaなどで配布物にしやすい）。

## 大会前に確認すること
- `config.js` の各競技の `schedule`（試合の進行順）は仮です。実際の順番に並べ替えてください。競技ごとに組み分けが違う場合は、その競技の `leagues`（クラスを時計回りに並べる＝隣どうしが対戦）と `schedule` を書き換えます。
- テストモード（API_URL が空）では結果がその端末内にしか保存されません。本番前にAで設定してください。
- 本番前に審判ページで適当に入力 → 本部ページで反映を確認し、スプレッドシートの `results` シートの行は削除してからスタート。
- 同率で準決勝進出が決まらない場合は、本部ページに順位を手動で決める欄が出ます（抽選・じゃんけんの結果を入力）。
- 入力ミスは、審判ページで同じ試合を選び直して「修正を保存」、または「この結果を取り消す」で直せます。
